======================================================================
1. SUMMARY
======================================================================
UniManage is a Tauri 2 desktop app. A Rust core asks each installed package manager (apt, flatpak, snap, mise,
npm, pnpm, pipx, uv) what it has installed. It saves the answers to SQLite, and a React UI shows them.
Milestone 1 can only read: nothing in it can install, update or remove software. The design aims to be safe, to
tolerate failures, and to be honest about what it doesn't know (an unknown value stays null/None and is never
guessed).

This session's only intended code change in Milestone 1 is one test, parses_real_npm12_output in
src-tauri\src\adapters\npm.rs. It runs the npm parsers on real output captured from npm 12.1 on Windows 11.

The code is split into layers:
 - model.rs: the data types every manager shares.
 - exec.rs: the only place that starts processes, behind the Runner trait.
 - adapters/: one parser per manager, behind the Adapter trait.
 - scanner.rs: runs all the adapters in parallel and keeps one failure from affecting the others.
 - db.rs: saves results to SQLite and reads them back.
 - commands.rs: the functions the UI is allowed to call.
 - lib.rs: wires everything together at startup.

--- src-tauri/src/model.rs: the shared vocabulary ---
 - Package holds every field from the spec. Anything that might be unknown is an Option<T>.
     * update_available: Option<bool> has three states: Some(true), Some(false), or None (unknown).
     * id is unique per installation source: apt:git:amd64, npm:typescript,
       flatpak:org.mozilla.firefox/x86_64/stable.
     * also_found_in lists other managers that have a package with the same name. It only reports the overlap;
       rows are never merged.
 - Package::new starts every field at "unknown"/None. management_status starts at Managed; External and Unknown
   exist but are reserved for later.
 - Enums: #[serde(rename_all = "snake_case")] makes them serialize as "up_to_date" and similar. The structs use
   camelCase, so latest_version reaches TypeScript as latestVersion.
 - Why Option everywhere: it puts the "never invent data" rule into the type system. The alternative, empty
   strings for unknown values, would let "" and "really empty" get mixed up.

--- src-tauri/src/error.rs ---
 - AppError is built with thiserror. Its variants are Spawn, Timeout, NonZero{status, stderr}, Parse,
   Unsupported, Db and Other.
 - From conversions from rusqlite::Error and serde_json::Error let the ? operator convert those errors
   automatically.
 - Custom Serialize turns the error into a plain string. That's the form Tauri needs to send an error back to
   JavaScript, where it arrives as a rejected promise.

--- src-tauri/src/exec.rs (original version): the Runner trait ---
    pub trait Runner: Send + Sync {
        fn which(&self, program: &str) -> Option<PathBuf>;
        fn run(&self, program: &str, args: &[&str]) -> Result<CmdOutput>;
    }
 - SystemRunner is the real implementation:
     * It finds the program with the "which" crate, then calls Command::new(path).args(args). Arguments are
       passed as an array, never as one shell string.
     * It sets LC_ALL=C, LANG=C and NO_COLOR=1 so the output is English, uncolored and parseable.
     * stdin is set to null, so a prompt can't hang the app.
     * On Windows it sets CREATE_NO_WINDOW so no console window flashes up.
 - Timeout: two "drain" threads read stdout and stderr into memory, so a full pipe buffer can't deadlock the
   child. The main thread polls try_wait() every 20 ms. After 60 s it kills the child and returns
   AppError::Timeout.
 - CmdOutput::ok() turns a non-zero exit code into AppError::NonZero, keeping at most 500 characters of stderr.
 - fake::FakeRunner (test builds only) lists which programs "exist" and maps a command line such as
   "npm ls -g --depth=0 --json" to canned output. This is why the parsers and the scanner can be tested on a
   Windows machine with no apt or snap.
 - Why a trait: the alternative is calling std::process::Command directly inside each adapter, but then no
   adapter could be tested without the real tool installed.

--- src-tauri/src/adapters/mod.rs: the Adapter trait ---
    pub trait Adapter: Send + Sync {
        fn id(&self) -> &'static str;  fn display_name(&self) -> &'static str;  fn binary(&self) -> &'static str;
        fn supports_updates(&self) -> bool { false }
        fn detect(&self, r: &dyn Runner) -> Option<PathBuf> { r.which(self.binary()) }
        fn version(&self, r: &dyn Runner) -> Result<String>;
        fn list_installed(&self, r: &dyn Runner) -> Result<Vec<Package>>;
        fn check_updates(&self, _r: &dyn Runner) -> Result<Vec<UpdateInfo>> { Err(Unsupported) }
    }
 - No install, update or uninstall methods, on purpose. A Milestone 1 adapter can't change the system because
   the methods for doing so don't exist.
 - Safe defaults: an adapter that doesn't override check_updates gets an Unsupported error, and
   supports_updates() defaults to false.
 - all() returns the 8 adapters as Vec<Box<dyn Adapter>>.
 - Two helpers:
     * first_line returns the first non-empty trimmed line.
     * non_empty returns None for "" or "-", the placeholder many CLIs print.
 - Design choice: each adapter splits into a thin "impl Adapter" that runs commands, plus pure parse_* functions
   that take &str. The pure functions are what the tests exercise.

--- The adapters, one by one ---
 apt
   Detect binary: dpkg-query
   List: dpkg-query -W -f <FMT> (tab-separated), plus apt-mark showmanual
   Update check: apt list --upgradable
   Notes: Keeps only rows whose status starts with "ii" (fully installed), so "rc" (config-only) rows are
   skipped. installReason (manual/automatic) is added only if apt-mark returned something. The version comes
   from apt --version, not dpkg. Kind = System.
 flatpak
   Detect: flatpak
   List: flatpak list --app/--runtime --columns=...
   Update check: flatpak remote-ls --updates --columns=application,version,branch
   Notes: If there is no version, falls back to the branch (for example 46). The id includes arch and branch.
 snap
   Detect: snap
   List: snap list (columns split on whitespace, header skipped)
   Update check: snap refresh --list
   Notes: core/bare/snapd, or notes containing base/snapd, mean Runtime; everything else is Application.
   Tracking is shown as "channel latest/stable".
 mise
   Detect: mise
   List: mise ls --json
   Update check: mise outdated --json
   Notes: Skips entries with "installed": false (configured but not installed). One package per tool VERSION,
   with id mise:node@22.1.0.
 npm
   Detect: npm
   List: npm ls -g --depth=0 --json, plus npm root -g
   Update check: npm outdated -g --json
   Notes: The list command doesn't check the exit code, because npm exits non-zero for odd trees but still
   prints valid JSON. For the update check, exit code 1 means "something is outdated". Global packages only.
 pnpm
   Detect: pnpm
   List: pnpm ls -g --depth=0 --json (an array of roots)
   Update check: pnpm outdated -g --format json
   Notes: Same exit-code-1 handling as npm for outdated.
 pipx
   Detect: pipx
   List: pipx list --json (venvs -> metadata.main_package)
   Update check: none
   Notes: supports_updates = false, so status stays "unknown". Missing venvs is a Parse error.
 uv
   Detect: uv
   List: uv tool list (text: "name vX", then "- exe" lines)
   Update check: none
   Notes: The "- exe" lines are attached to the previous tool as the "executables" metadata.

--- src-tauri/src/scanner.rs ---
 - scan_adapter(a, r, check_updates) works through these steps in order and returns an AdapterResult
   (info, packages: Option<Vec>, outcome):
     * detect finds nothing: result is "not detected", which is NOT an error.
     * version is best effort: .ok(), so a failure becomes None.
     * list_installed fails: it stores last_error and sets packages = None.
     * check_updates runs only if requested AND supports_updates(). If it fails, the error goes to
       update_error, but the package list is kept.
 - apply_updates: after a SUCCESSFUL update check, any package not listed is marked UpToDate/Some(false).
   Matching is by name, and an update whose latest_version equals the installed version is ignored. If the
   check never ran, packages keep Unknown/None.
 - scan_all:
     1. begin_scan inserts a "running" row and the "started" event is emitted.
     2. Inside std::thread::scope, it starts ONE THREAD PER ADAPTER. Each runs scan_adapter wrapped in
        catch_unwind, so a panic turns into an "internal error: adapter panicked" result instead of crashing
        the app. The Unavailable dummy adapter only exists to build that result.
     3. Each thread sends (id, result) over an mpsc channel. The scope body receives results in the order they
        finish, saves each one through Db::save_manager with a short lock, and emits a "manager" event
        (done/total, plus a message like "npm: 2 packages" or "apt: not installed").
     4. The scan status is "completed" if nothing failed, "partial" if some but not all detected managers
        failed, otherwise "failed". finish_scan stores the per-manager outcomes as JSON, emits "finished", and
        returns the newest ScanRecord.
 - Why threads instead of async: the work is blocking process I/O, so scoped OS threads are the simplest fit.
   Scoped threads can borrow adapters, runner and db without Arc. The alternative, tokio async processes,
   would need async versions of the Runner and the parsers' callers.

--- src-tauri/src/db.rs and migrations/001_init.sql ---
 - The schema creates all 9 spec tables: package_managers, installed_packages, package_metadata,
   package_dependencies, operations, operation_logs, environment_manifests, application_settings, scan_history.
     * Only package_managers, installed_packages, package_metadata and scan_history are used so far.
       (Note from main session: operations and operation_logs are now used by the new operation pipeline.)
     * update_available INTEGER is nullable, so NULL means unknown.
     * Foreign keys use ON DELETE CASCADE, which works because init runs PRAGMA foreign_keys=ON.
 - migrate(): MIGRATIONS is an array of SQL files compiled into the binary with include_str!.
   PRAGMA user_version stores how many have run. Each pending migration runs in a transaction, which then sets
   user_version = i+1. Adding 002_x.sql means appending it to the array.
 - save_manager(info, packages), all in one transaction:
     1. Upsert the manager row (INSERT ... ON CONFLICT(id) DO UPDATE).
     2. replace = packages.is_some() || !info.detected. If true, delete that manager's packages (metadata goes
        with them through the cascade) and insert the new list.
     3. If the manager is detected but failed (packages == None), the old rows are kept. The code comment
        explains why: "stale data beats silently empty data". A manager that has disappeared gets its rows
        removed.
 - list_packages loads all metadata into a map first, then the packages sorted case-insensitively by name.
   Enums are converted back from their snake_case text. It finishes with annotate_overlaps.
 - annotate_overlaps normalizes names (lowercase, "_" and "." become "-"), so "git" (apt) and "Git" (snap) each
   get the other's manager in also_found_in.
 - fail_interrupted_scans: at startup, any scan still marked "running" (left over from a crash) is set to
   "failed".
 - Other functions: list_managers counts packages per manager with a subquery. recent_scans(limit) returns
   ScanRecords with details parsed back to JSON. setting() exists but nothing uses it yet.

--- src-tauri/src/commands.rs and lib.rs ---
 - lib.rs::run() setup:
     * Creates the app data directory and opens unimanage.sqlite there.
     * Marks interrupted scans as failed.
     * Calls app.manage(AppState{db: Arc<Mutex<Db>>, scanning: Arc<AtomicBool>}).
     * Registers 4 commands. main.rs just calls unimanage_lib::run().
 - start_scan (an async command):
     * compare_exchange(false, true) sets the flag atomically. If a scan is already running, it returns
       "a scan is already running".
     * It clones the two Arcs and does the blocking work in tauri::async_runtime::spawn_blocking, so the IPC
       thread isn't blocked.
     * It builds adapters::all() and SystemRunner::default(), calls scan_all, and the emit closure does
       app.emit("scan-progress", p).
     * It resets the flag, then returns the ScanRecord.
 - get_packages, get_managers, get_scan_history(limit=20): read-only; each goes through with_db, which locks
   the mutex.
 - capabilities/default.json grants only core:default. There is no shell, filesystem or process plugin, so the
   webview can't run programs itself; only the Rust commands can.
 - tauri.conf.json sets a strict CSP (default-src 'self'; IPC connections only).

4. WHAT HAPPENS AT RUNTIME: ONE SCAN ON THIS WINDOWS MACHINE
======================================================================
 1. Startup. run() opens %APPDATA%\dev.unimanage.app\unimanage.sqlite (the agent didn't confirm the exact folder
    Tauri uses on Windows; check app_data_dir), runs migrations, and marks old "running" scans as "failed".
    useInventory loads the empty lists, and Overview shows "No scan yet".
 2. The user clicks "Scan system". inv.scan() -> invoke('start_scan', {checkUpdates: true}).
 3. start_scan flips "scanning" from false to true, then spawn_blocking runs scan_all with 8 adapters.
 4. begin_scan inserts a scan_history row (say id 1, status "running"). It emits
    {phase:"started", done:0, total:8}, so the UI shows "Scanning package managers 0%".
 5. 8 threads start. For apt, which("dpkg-query") returns None, so the result is not detected and has no
    error. The same happens for flatpak, snap, mise, pnpm, pipx and uv.
 6. The npm thread:
     - which("npm") finds npm (on Windows probably npm.cmd via PATHEXT; see risks).
     - "npm --version" gives "12.1.0".
     - "npm ls -g --depth=0 --json" returns JSON like the test fixture, so parse_ls produces 2 packages:
       npm:@qwen-code/qwen-code 0.24.0 and npm:npm 12.1.0.
     - "npm root -g" gives something like C:\Users\...\npm\node_modules, so installation_path =
       C:\...\node_modules/npm (mixed separators).
     - "npm outdated -g --json" exits 1 (allowed) and parse_outdated returns [npm -> 12.2.2].
     - apply_updates marks npm as "available" with latest 12.2.2, and qwen-code as "up_to_date".
       update_count = 1.
 7. Each result is saved as it arrives. For each undetected manager, save_manager upserts the manager row and
    deletes its packages (none exist). For npm it deletes the old npm rows and inserts 2 packages plus their
    scope=global metadata. Each save emits a progress event, for example
    {phase:"manager", manager:"npm", done:5, total:8, message:"npm: 2 packages"}.
 8. The scan finishes. No failures, so the status is "completed". finish_scan(1, "completed", 2, 1, outcomes)
    runs, then the "finished" event, and the command returns the ScanRecord. The flag goes back to false.
 9. The frontend reloads. reload() -> Overview shows "Installed packages 2", "Updates available 1",
    "Package managers 1 / 8", "Last scan completed". The Installed page shows npm with a "-> 12.2.2" badge.

5. CONCEPTS USED
======================================================================
 - Trait / dyn Trait / Box<dyn Trait>: Rust's interfaces (like a C# interface). &dyn Runner means "any type that
   implements Runner", chosen at runtime. Example: fn f(r: &dyn Runner) accepts both SystemRunner and
   FakeRunner.
 - Send + Sync: marker traits meaning a type can be moved to another thread (Send) or shared between threads
   (Sync). They're required because the scanner shares adapters across threads.
 - Result<T, E>, ? and Option: errors are ordinary return values. ? returns early on Err, converting the error
   through From, so it works a bit like "await" that rethrows. .ok() turns a Result into an Option. Example:
   r.run(..)?.ok()? means "fail on spawn error, then fail on non-zero exit".
 - thiserror: a derive macro that writes Display/Error for an enum. Example: #[error("timed out after {0}s")].
 - serde rename_all: controls JSON field names. latest_version becomes latestVersion with camelCase; UpToDate
   becomes up_to_date with snake_case.
 - Raw strings r#"..."#: string literals where " and \ need no escaping, which makes JSON fixtures readable.
   In the test, \\ inside JSON is a JSON escape, not a Rust one.
 - std::thread::scope: threads that are guaranteed to finish before the scope ends, so they can borrow local
   variables (C# has no direct equivalent; think Parallel.ForEach that can safely use stack references).
 - mpsc::channel: a thread-safe queue with many senders and one receiver. Once every tx is dropped, rx.iter()
   ends. That's why there's an explicit drop(tx).
 - catch_unwind / AssertUnwindSafe: catches a panic (an unrecoverable error) and returns it as an Err, like a
   try/catch around a crash. AssertUnwindSafe is the programmer promising the captured state won't be left
   inconsistent.
 - AtomicBool::compare_exchange: atomically means "if the value is false, set it to true, and tell me whether
   that worked". It's a lock-free "only one scan at a time" guard, similar to Interlocked.CompareExchange in C#.
 - Arc<Mutex<T>>: shared ownership (Arc) plus exclusive access (Mutex). lock() returns a guard that unlocks
   when dropped, so a lock taken inside one statement is released at the end of that statement.
 - Tauri commands, events and state: #[tauri::command] functions are called from JS with invoke('name', args).
   app.emit pushes events that JS receives with listen. app.manage(x) stores a singleton that commands receive
   as State<'_, T>, which is dependency injection.
 - Tauri capabilities and CSP: capabilities decide which built-in APIs the webview may call. The CSP limits
   where the page can load code and connect.
 - spawn_blocking: runs blocking code on a thread pool meant for it, so the async runtime isn't starved. It's
   the same idea as Task.Run in C# for CPU or blocking work.
 - SQLite UPSERT: INSERT ... ON CONFLICT(id) DO UPDATE SET ... inserts, or updates if the key already exists.
 - PRAGMA user_version: an integer slot in the database file, used here as the schema version number.
 - WAL: SQLite's write-ahead-log mode, which lets readers and a writer work at the same time.
 - Transaction: everything between begin and commit() applies all at once or not at all. If the tx is dropped
   without a commit, it rolls back.
 - include_str!: embeds a file's text into the binary at compile time, so the migrations ship inside the
   executable.
 - #[cfg(test)] / #[cfg(windows)]: conditional compilation. That code only exists in test builds or on Windows.
 - let ... else: "let Some(path) = a.detect(r) else { return ...; };" either unwraps the value or leaves the
   function.
 - React hooks: useState holds state, useEffect runs side effects after render and returns a cleanup function,
   useCallback/useMemo keep a function or computed value between renders, and useRef holds a mutable value that
   doesn't trigger a re-render (used here as the "busy" flag).
 - StrictMode: in development, React mounts, unmounts and remounts components to expose effects that don't
   clean up properly. That's why the effect uses a "cancelled" flag.
 - Tailwind and cn(): utility CSS classes. cn joins class names conditionally (clsx) and resolves conflicts
   (twMerge): cn('p-2', 'p-4') -> 'p-4'.

6. SIDE EFFECTS AND RISKS (MOST SERIOUS FIRST)
======================================================================
 1. The build was broken at the time of the report by the concurrent edit to exec.rs, at lines 151-152 and
    155-156: literal newline and CR characters instead of \n and \r escapes. (Fixed since; see top note.)
    That run_streaming code is also a new process-execution path and should get its own review; the agent
    didn't review it.
 2. The scan flag can get stuck at true. flag.store(false) only runs if scan_all returns normally. A panic
    outside the per-adapter catch_unwind (in emit, in the database code, or in scan_all itself) skips it. Every
    later scan would then answer "a scan is already running" until the app restarts. A drop guard, or resetting
    the flag after .await in start_scan, would fix this.
 3. Duplicate ids in one manager's output break that whole manager. save_manager inserts metadata with a plain
    INSERT, and (package_id, key) is the primary key. If a parser ever returns the same id twice (for example
    mise listing the same tool@version twice), the metadata insert fails, the transaction rolls back, and the
    manager is reported as failed. Related: rows are deleted before being reinserted, so the
    ON CONFLICT ... SET last_seen_at clause effectively never fires, and first_seen_at is reset on every scan.
    It currently means "time of the last scan".
 4. Update matching only looks at names. For mise, every installed version of "node" is matched against the one
    "node" entry from "mise outdated". Example: with node 18 and 22 installed and latest 22.5, both are marked
    "available".
 5. Windows .cmd files and "no shell". On Windows which("npm") probably resolves to npm.cmd. The agent's
    understanding is that Rust's standard library runs .bat/.cmd files through cmd.exe, quoting the arguments
    itself. Today's arguments are fixed constants, so there is no injection risk. It matters for the planned
    write operations, where package names become arguments: strict name validation (HANDOFF TODO #2) is
    required. To confirm, look up Rust's std::process::Command docs on batch files.
 6. The timeout and child processes. kill() only kills the direct child. If that child launched a grandchild
    that keeps stdout open (for example cmd.exe -> node), then after a normal exit out.join() can block
    indefinitely, since the timeout loop has already ended. After a timeout, the drain threads are left
    running. This is unlikely for short read commands but fragile.
 7. Small inaccuracies:
     - npm installation_path joins with "/", giving mixed separators on Windows.
     - apt detection uses dpkg-query, but the version comes from apt (a missing apt just gives version None).
     - Status edge case: a save error for an UNDETECTED manager counts as a failure but not as detected, which
       can turn the status into "failed" when "partial" would be more accurate.
     - uv's text parser would treat any unexpected stdout line with two words as a package.

8. CHECK YOUR UNDERSTANDING
======================================================================
 1. During a rescan, "npm ls" exits with a spawn error but npm is still found on PATH. What happens to the npm
    rows from the previous scan, and which line decides that?
 2. Why does a pipx package show "Unknown" in the Update column instead of "Up to date", even after a
    completely successful scan?
 3. What two things does parses_real_npm12_output prove that the old hand-written parses_ls fixture didn't?

ANSWERS
 1. They are kept. scan_adapter returns packages: None with detected = true, and save_manager computes
    replace = packages.is_some() || !info.detected = false, so the DELETE is skipped. Only the manager row is
    updated, with last_error set. The Overview shows the "failed to report... data is kept" banner.
 2. Pipx doesn't override supports_updates(), which defaults to false. So scan_adapter never calls
    check_updates, and apply_updates never runs for pipx. Package::new leaves update_status = Unknown and
    update_available = None, and the design rule is never to guess.
 3. (a) Real npm 12 entries have no "resolved" field and have extra fields like "overridden"; the parser
    tolerates both, and installation_source becomes None. (b) Scoped package names containing "/"
    (@qwen-code/qwen-code) parse correctly. As a bonus, real "outdated" output with extra fields (dependent,
    location) still gives the correct "latest".
